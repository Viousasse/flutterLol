# T17 — Chargements parallèles : ne perdre aucune erreur

Lis d'abord `docs/agents/COORDINATION.md`.

## Problème (relevé par T14)
Plusieurs écrans lancent deux ou trois chargements **en parallèle** puis les
attendent l'un après l'autre :

```dart
final championsRequest = widget.loadChampions();
final datasetRequest = widget.loadDataset();
final loadedChampions = await championsRequest;   // si datasetRequest échoue
final loadedDataset = await datasetRequest;       // pendant ce temps, personne
                                                  // ne l'écoute encore
```

Si le **second** futur échoue avant que le premier soit terminé, son erreur n'a
aucun auditeur : Dart la signale comme **exception non rattrapée** (le `try/catch`
ne la voit que plus tard, quand on arrive au `await` du second). En production,
c'est une erreur perdue dans les journaux ; en test, un échec « uncaught async
error ».

## À faire
1. Dans chaque fichier ci-dessous, remplace ce motif par un seul
   `await Future.wait([...])` (ou, si les types diffèrent, un enregistrement avec
   `(a, b).wait` de Dart 3), de façon que **toutes** les erreurs soient écoutées
   dès le départ, **sans changer** le comportement visible (même message d'erreur,
   même « Réessayer », mêmes données). Si plusieurs futurs échouent, c'est la
   première erreur qui est affichée.
   - `lib/builds/builds_page.dart` (objets, champions, store)
   - `lib/builds/build_editor_page.dart` (objets, champions)
   - `lib/counters/counters_page.dart` (champions, matchups)
   - `lib/strengths/strengths_page.dart` (champions, matchups)
   - `lib/draft/draft_page.dart` (champions, matchups)
   - `lib/quiz/quiz_page.dart` (champions, objets, matchups, score ; **le chargement
     des matchups est déjà tolérant** : `_loadMatchups` renvoie un jeu vide s'il
     échoue — garde ça tel quel)
   - `lib/search/search_page.dart` (champions, objets)
   - `lib/draft/draft_history_page.dart` (store + champions, si le motif y est)
   Cherche aussi avec Grep tout autre `Request = ` / double `await` de futurs
   créés auparavant dans `lib/**/*_page.dart` et traite-les de la même façon (note
   au journal ceux que tu ajoutes).
2. **Tests** : pour chaque page de ta liste qui a déjà un fichier de tests d'écran
   (`test/counters/counters_page_test.dart`, `test/strengths/strengths_page_test.dart`,
   `test/builds/builds_page_test.dart`, `test/draft/draft_page_flow_test.dart` ou
   un fichier voisin, `test/quiz/…`), ajoute **dans un nouveau fichier**
   `test/<feature>/<page>_load_errors_test.dart` le cas : « le second chargeur
   échoue avant le premier » → l'écran d'erreur avec « Réessayer » s'affiche, aucun
   `uncaught async error`, et un second essai réussi affiche les données. Pour
   provoquer l'ordre, le premier chargeur est un `Completer` qu'on termine après
   l'échec du second. Réutilise l'outillage des tests existants (voir
   `test/counters/counter_pages_support.dart`) sans le modifier. Pas de
   `pumpAndSettle` (COORDINATION §3).
3. Ne change aucune autre logique.
