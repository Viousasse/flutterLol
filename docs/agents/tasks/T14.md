# T14 — Tests d'écran : contre-picks, points forts, builds, composition

Lis d'abord `docs/agents/COORDINATION.md`.

## But
La draft est testée de bout en bout (`test/draft/draft_page_flow_test.dart` : la
page reçoit ses chargeurs en paramètres, aucune dépendance au réseau). Les pages
**Contre-picks**, **Points forts**, **Mes builds** (liste + import) et
**Composition** ne sont testées que par leurs services. Ajoute des tests
d'écran, après avoir rendu leurs sources de données **injectables** (même
approche que `DraftPage` : paramètres du constructeur avec la valeur par défaut
actuelle).

## À lire
`lib/draft/draft_page.dart` (début : paramètres `loadChampions`, `loadDataset`,
`loadDetail`, `botThinkingDelay`) et `test/draft/draft_page_flow_test.dart`
(outillage : champions fictifs, `_settle` par `pump` répétés — **pas de
`pumpAndSettle`** : COORDINATION §3), `lib/counters/counters_page.dart`,
`lib/strengths/strengths_page.dart`, `lib/builds/builds_page.dart`,
`lib/team/team_page.dart`, `lib/builds/services/build_import.dart`,
`lib/shared/widgets/paste_code_dialog/paste_code_dialog.dart`.

## À faire
1. **Injection** (paramètres optionnels, valeurs par défaut = comportement
   actuel, aucun changement visible) :
   - `CountersPage` / `StrengthsPage` : `loadChampions`, `loadDataset`.
   - `BuildsPage` : `loadItems`, `loadChampions` (le `BuildStore` reste le
     store statique : `BuildStore.reset()` à ajouter **s'il manque**, réservé aux
     tests, `@visibleForTesting`, comme `DraftHistoryStore.reset()`).
   - `TeamPage` : `loadChampions`, `loadDetail`, `loadProfile` (profil de voies).
2. **Tests** (un fichier par page, dans `test/<feature>/`) :
   - Contre-picks : état de chargement, échec + « Réessayer » (puis succès),
     choix de l'adversaire via la feuille (filtre de rôle présent), liste de
     contre-picks triée, filtre de voie, mention « peu de données » pour un
     bilan peu fiable, `DataSourceNote` affichée.
   - Points forts : mêmes cas + sections « FORT CONTRE » / « DIFFICILE CONTRE ».
   - Builds : liste vide (message), liste avec builds, suppression avec
     confirmation, **import** (boîte « Importer une build » : code valide → la
     build apparaît et un message le dit ; texte invalide → la boîte reste
     ouverte avec l'erreur), bouton de partage qui copie le texte (vérifie le
     presse-papiers avec le canal de test `SystemChannels.platform`).
   - Composition : cinq cases vides, choix d'un champion via la feuille (filtre
     de rôle présélectionné sur le rôle de la case), analyse affichée une fois
     des champions placés (réutilise les helpers de `test/draft/draft_support.dart`
     pour fabriquer des `ChampionDetail`).
3. N'écris pas de test qui dépend du réseau ou de l'horloge réelle.
