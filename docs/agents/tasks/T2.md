# T2 — Outil de génération des matchups : mise à jour incrémentale

Lis d'abord `docs/agents/COORDINATION.md`.

## But
`tool/generate_matchups.dart` génère `assets/data/champion_matchups.json` à
partir de l'API Riot (clé dans la variable d'environnement `RIOT_API_KEY`).
Il sait déjà : `--matches N`, `--output <fichier>`, `--resume`, `--merge-with
<fichier>`, sauvegarde de progression toutes les 100 parties, parties 404
ignorées. Le fichier actuel mélange les patchs 16.16 à 16.19 sans les
distinguer : les vieilles parties pèsent autant que les récentes. Il faut
pouvoir **mettre à jour sans tout refaire**, en faisant **vieillir** l'existant.

## À faire
1. **`--decay <0..1>`** (défaut `1`, c'est-à-dire sans effet) : applique ce
   facteur aux bilans du fichier `--merge-with` **avant** de les additionner aux
   nouveaux. `games` et `wins` sont arrondis ; `wins` ne dépasse jamais `games` ;
   une entrée qui tombe à 0 partie est retirée. Le champ `matches` du fichier de
   sortie additionne aussi les parties pondérées (arrondies).
2. **`--min-patch X.Y`** (ex. `16.19`) : ignore (en les marquant traitées) les
   parties dont le patch est antérieur. Comparaison numérique
   `majeur.mineur`, pas alphabétique (`16.9` < `16.10`).
3. Extrais la logique pure dans **`tool/matchup_tally.dart`** (décroissance,
   comparaison de patchs, fusion, étiquette de plage de patchs) pour la tester.
   `tool/generate_matchups.dart` l'importe. Ne change pas le format du JSON de
   sortie lu par l'application (`lib/matchups/models/matchup.dart`) ; tu peux
   ajouter un champ informatif `patches` (`{"16.19": 4045, …}`) **seulement si**
   `MatchupDataset.fromJson` l'ignore sans erreur (vérifie, et couvre-le d'un
   test dans `test/matchups/`).
4. **`tool/README.md`** (en français) : prérequis (clé Riot de développement,
   valable 24 h ; limite 100 requêtes/2 min ; durée ≈ 1 h pour 3 000 parties),
   commande de régénération complète, commande de **mise à jour du patch**
   (`--merge-with assets/data/champion_matchups.json --decay 0.5 --min-patch …`),
   reprise après interruption, comment **installer** le fichier (copier vers
   `assets/data/`, lancer `flutter test`), comment **vérifier la couverture**
   (combien de champions ont au moins un contre-pick à 8 parties), ce que
   signifie l'étiquette de patch, rappel de ne jamais écrire la clé dans un
   fichier.
5. Tests : `test/tool/matchup_tally_test.dart` (importe depuis `../../tool/…`).
