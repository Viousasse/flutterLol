# T7 — Codes de partage (builds et drafts)

Lis d'abord `docs/agents/COORDINATION.md` (surtout §8, contrat T7 → T13).

## But
Aujourd'hui on copie un **texte** lisible d'une build ou d'une draft
(`BuildShareText`, `DraftShareText`). Il faut aussi un **code** compact qu'un
ami peut coller dans son appli pour retrouver la build ou la draft. T13
fabriquera les écrans d'import ; toi, la logique.

## À lire
`lib/builds/models/build.dart`, `lib/builds/services/build_share_text.dart`,
`lib/draft/models/draft_record.dart`, `lib/draft/services/draft_share_text.dart`,
`test/builds/build_share_text_test.dart`, `test/draft/draft_history_test.dart`
(la partie `DraftShareText`).

## À faire
1. `lib/builds/services/build_share_code.dart` : `BuildShareCode.encode(Build)`
   → `LOLB1.<base64url sans padding>` d'un JSON compact `{n, c, i}` (nom,
   championId ou absent, ids d'objets). `decode(String texte)` → `Build?` : **cherche**
   le premier code `LOLB1.…` dans un texte quelconque (le code est souvent collé
   dans tout le message de partage), renvoie `null` s'il est absent, tronqué,
   mal encodé ou invalide ; borne la taille (nom ≤ 60 caractères, ≤
   `Build.maxItems` objets, ids d'objets en chaîne) ; génère un **nouvel `id`**
   (`BuildStore.newId()`).
2. `lib/draft/services/draft_share_code.dart` : même principe, préfixe
   `LOLD1.`, pour `DraftRecord` (équipes, bannis, noms des champions, vainqueur,
   scores, verdict, noms des joueurs, `versusFriend`, date, `assisted` si T10 l'a
   déjà ajouté — sinon ne le code pas). `decode` → `DraftRecord?` avec un
   **nouvel `id`** et la `playedAt` d'origine ; valide les longueurs (5 rôles).
   Rends le format **extensible** (un champ de version dans le préfixe, champs
   inconnus ignorés).
3. Les textes de partage se terminent par une ligne `Code : <code>` :
   modifie `build_share_text.dart` et `draft_share_text.dart` (tu en es le seul
   propriétaire) et **mets à jour leurs tests existants**
   (`build_share_text_test.dart`, la partie partage de `draft_history_test.dart`).
   `BuildShareText.of` doit pouvoir recevoir le `Build` (il l'a déjà) pour
   fabriquer le code ; pour la draft, le `DraftRecord` suffit.
4. Tests : `test/builds/build_share_code_test.dart` et
   `test/draft/draft_share_code_test.dart` — aller-retour exact ; code noyé dans
   un texte ; texte sans code ; code tronqué/corrompu ; base64 invalide ; JSON
   invalide ; bornes ; nouvel `id` à chaque `decode` ; le texte de partage
   contient bien le code et celui-ci se relit.

## Fichiers qui t'appartiennent
Les deux services de code, `build_share_text.dart`, `draft_share_text.dart`, leurs
